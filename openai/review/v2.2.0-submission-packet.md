## Founder configuration and release sequence

1. After review and merge, rebuild with the commands in openai/README.md and run
   verify-dist immediately before upload. Keep checksums.json with the review record.
   This batch also rebuilds Citation Check, AI Compliance and Privacy Review at
   0.2.0 because the shared workflow fragments were re-pinned. Re-test those
   candidates before uploading them as part of the same batch.
2. Arrange one domain-verification hostname for each plugin. Preserve the
   existing Ansvar Gateway challenge token. OpenAI requires the exact token,
   plain text, at `https://<challenge-base-host>/.well-known/openai-apps-challenge`.
   The host must be the MCP host or an eligible parent; an arbitrary sibling
   subdomain is not sufficient. The shared packaged endpoint remains unchanged.
   Confirm an unused eligible host is available before connecting this draft.
   If those hosts are already assigned, commission the separate gateway-values
   change for a plugin-specific MCP hostname, certificate, routing and challenge
   token; then update the package's one MCP URL through a reviewed release and
   rebuild. A suggested alias to reserve in that case is
   `vulnerability-management.gateway.ansvar.eu`, with its own challenge URL.
   This alias is a proposal, not configured or tested by this packaging PR.
   Do not overwrite another plugin's token, use a token list, or submit with an
   unverified hostname. Resolve the same requirement for each parked plugin.
3. Register/identify the plugin's OAuth client and add its actual client id to
   the gateway's ChatGPT-client set through the authorized gateway values path.
   Verify ChatGPT responses contain no upgrade, subscription-plan or checkout
   messaging, including refusals and report next actions. The local skill
   boundary does not prove server-side response compliance. No gateway values
   or OAuth configuration were changed here.
4. Authorize the portal MCP connection with a dedicated non-internal reviewer
   account, not an Ansvar internal seat. Enter login URL, workspace/tenant and
   sign-in instructions privately. Keep credentials out of the ZIP, repository,
   chat and report. Check discovered tools and current scan findings; the focused
   skill does not restrict the gateway's server-side tool surface.
5. Install in ChatGPT and test with Free, Premium and Team reviewer accounts,
   synthetic products and scanner exports. Exercise programme availability,
   admitted and refused starts, all human gates, final report delivery, first
   snapshot, cursor continuation, stale/expired feeds, scanner reconciliation,
   no-scanner stopping and unavailable control mappings. Test every catalog case
   and confirm unsupported requests redirect or refuse. Record observations;
   do not claim the expected cases passed before running them.
6. Record the walkthrough across supported clients; provide its URL, reviewer
   account details and any required policy attestations. Resolve connection,
   domain and safety/tool-scan failures, then submit the selected draft. The
   founder publishes after approval. No submission is authorized for this agent.
